# 为 Chrome 配置环境并检测

需要同时使用普通 Chrome 和 Aura Chrome 时，先为应用开启独立浏览器数据目录，再选择环境配置启动。不同环境使用不同目录；同一应用和环境再次启动时保留登录、书签和设置。

## 配置代理，检测出口并填入时区

1. 打开“环境配置”，编辑需要使用的 Profile。
2. 如需代理，在 Profile 中配置 HTTP 或 SOCKS5 的服务器地址和端口；Chrome 与出口检测共用这份配置。
3. 点击检测出口／查询时区。IP 由本次请求自动检测，只读，不需要手填。
4. 核对结果中的 IP、网络来源、IANA 时区和 Windows 时区，确认后填入。
5. 保存配置，再重新启动目标应用。已经运行的实例继续使用启动时的设置。

HTTP／SOCKS5 代理只用于受支持的 Chrome 和 Aura 出口／时区检测，不修改 Windows 系统代理。SOCKS5 使用代理侧 DNS；代理无法连接时明确失败，不自动回退直连。本轮配置无认证端点，不支持在地址中嵌入用户名或密码。

未配置 Profile 代理时，旧应用的系统或手填代理参数继续保留；查询展示的是 **Aura 当前网络出口**，不读取 Chrome 扩展或网站分流配置。即使使用相同代理，目标站点也可能受到分流规则影响，可用下方检测页继续核对。

配置 Profile 代理后，若应用参数中已有代理控制开关，请先移除冲突参数。更改代理后关闭对应 Chrome 再启动，不能把新配置的检测页转交给旧代理实例。Host 启动不使用 Profile 代理。

查询只填入两个时区字段，不调整地区、语言、DNS 或身份信息。查询失败、缺少具体时区或找不到有效 Windows 映射时，原配置保留，可以手动选择。国家代表时区和 UTC 偏移不能代替具体时区。

当前支持的国家和地区以中文显示；输入中文名称或地区代码都可以搜索。例如“日本”和 `jp` 命中同一选项，保存值仍为 `JP`。

## 使用独立浏览器数据目录

在 Chrome 应用的编辑界面开启独立数据目录并保存。目录按应用和实际选择的 Profile 分配，临时“运行于”其他 Profile 不会修改默认 Profile；Host 使用单独的目录。

- 首次使用新目录时需要重新登录、设置书签或安装扩展。Aura 不复制宿主 Chrome 的数据。
- 已手填 `--user-data-dir` 时，移除该参数或关闭自动目录，二者不能同时使用。
- `--profile-directory` 选择数据根目录内的 Chrome 用户配置，不能代替独立数据根。
- 对应目录已有浏览器占用或 Aura 无法确认其环境时，关闭那个浏览器后再启动。Aura 不强制结束已有 Chrome。
- 关闭开关或删除 Aura 中的应用、环境配置，不会自动删除浏览器数据。

此设置只适用于受支持的 Chrome 可执行应用。旧配置默认关闭，原有手填参数继续按原方式使用。

## 在对应浏览器中检测

在“应用”页选择 Chrome，再选择要检测的环境，打开以下两个检测入口之一：

- [IPPure Claude 环境检测](https://ippure.com/claude.html)
- [Net.Coffee Claude 检测](https://ip.net.coffee/claude/)

检测入口沿用该应用的参数、目录和环境，不调用系统默认浏览器，也不永久改写应用参数。已运行浏览器只有在实际环境与启动配置可确认匹配时才复用；保存了新 Profile 后，先关闭对应 Chrome 再启动，才能检测新配置。

页面显示出口、时区、语言、DNS、WebRTC 等检查结果。分流网络可能有多个出口，以目标网站对应的出口为参照。站点评分属于第三方判断，网页打不开不影响已经启动的应用继续使用。

## 在运行实例页管理应用

“环境配置”页只维护配置；启动和浏览器检测在“应用”页进行。打开“运行实例”查看状态、刷新、停止实例或展开诊断，可按应用筛选。

实例页同时保留本次界面管理的会话与后台 Supervisor 管理的运行记录。历史工作区启动的 Chrome 使用 **兼容启动**：强制注入并确认根进程载入匹配配置，不提供其他工作区应用的严格入口门禁保证；沙箱子进程的覆盖以实际观测为准。

若后台 Supervisor 本身重启，旧兼容实例会显示 `TrackingLost`，Aura 只观测原 Job，不自动接管窗口。保持新 Supervisor 在线，关闭对应 Chrome 后在实例页刷新；确认原 Job 归零后才能重新运行。如果浏览器在 Supervisor 离线期间已完全退出、原 Job 已消失，缺少全树结束证据，记录会保留 `TrackingLost`。

## 退出 Aura 后继续使用

可以退出 Aura 界面，已经启动的 Chrome 仍继续运行。Profile 会话的后台进程保留到目标进程树结束，负责后继进程的环境继承；不要把退出界面理解为强制结束全部会话后台进程。

Aura 只提供进程级环境视图，不修改宿主全局时区，不提供文件或权限隔离。覆盖范围取决于应用使用的系统接口和浏览器进程模型。
