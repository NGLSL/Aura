# Aura v0.3.2

此版本修正 Chrome / Edge 网页语言与 Environment Profile 不一致的问题，并补齐使用 `CreateProcessAsUserW` 创建子进程时的 Profile 继承。打包应用的 Runtime Profile 通信改为按进程 ID 定位，避免并行实例争用同一管道。

## 本版内容

- Aura 启动新的 Chrome 或 Edge 主进程时，把 Profile 的 Locale 写入 `--lang` 和 `--accept-lang`；若启动参数已有冲突值，以 Profile 为准。浏览器已有的中文用户数据不会再使新进程的页面 `Intl` 默认区域和 `navigator.language` 偏离 `en-US` Profile。
- Runtime 接管 `CreateProcessAsUserW` 创建的受管理子进程，使其按同一 Profile 初始化；Probe 增加对应的父子进程检查。
- 打包应用按目标进程 ID 建立 Runtime IPC 管道。并行启动实例时，各实例读取自己的 Profile，管道名称被占用时会明确失败。
- GUI 与 CLI 提示 Chrome / Edge 网页沙箱下的部分原生环境信息覆盖限制。GUI 同时说明语言设置只在新建浏览器进程时生效。

## 验证

- `cargo check --workspace --locked` 和从未注入的 Windows 宿主发起的 `cargo test --workspace --locked` 通过（305 通过、7 忽略）；x64/x86 Runtime 和安装包经清理后使用标准脚本构建，8 个暂存文件与本次 Release 输出的 SHA-256 逐项一致。发布页附有安装包大小与 SHA-256。
- 在隔离的 `zh-CN` 用户数据目录中，使用本版 Release CLI 和 Runtime 启动 Chrome 与 Edge：页面读取的 `Intl.DateTimeFormat`、`Intl.NumberFormat`、`navigator.language` 均为 `en-US`，时区为 `America/Los_Angeles`；浏览器主进程加载的 Runtime 哈希与本版 Release DLL 一致。
- 使用本版 Release CLI、Runtime 和 Probe，从独立宿主启动 `CreateProcessAsUserW` 测试：父子进程均加载 Runtime，读取 `GetUserDefaultLocaleName=en-US` 与 `LANG=en_US.UTF-8`。

## 升级与已知边界

下载安装包 `aura-setup.exe` 升级。重启 Aura 及需要新语言设置的浏览器进程；已经运行的 Chrome / Edge 主进程不会因 Aura 再次启动同一用户数据目录而重新读取语言参数。升级不会修改 Windows 全局 Locale、Region 或 Timezone。

Chrome / Edge 的沙箱渲染进程仍可能拒绝加载 Runtime，因此这些进程直接调用原生 Windows API 时仍可能看到宿主值。打包应用仍在激活后注入，启动早期可能先读取到宿主值。本次实机检查使用隔离浏览器实例；正式 `v0.3.2` 安装包的升级过程与用户现有浏览器会话尚未现场验证。EnvBox 不提供安全沙箱。
