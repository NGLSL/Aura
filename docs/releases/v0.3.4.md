# Aura v0.3.4

This patch release gives Aura a concise name in Windows Task Manager.

## Changes

- The GUI executable's Windows file description is now **Aura**, replacing **EnvBox process-scoped environment virtualization**. Task Manager uses this description to identify the application.
- The executable's Windows product name is also **Aura**, matching the application window and installer.

## Upgrade behavior

In Aura v0.3.3, open Settings, check for updates, then download and install the update. You can also download `aura-setup.exe` from this release and run it directly. Finish the installation wizard and reopen Aura to use the new executable and display name.

The installer retains the existing installation directory and local configuration. Applications already launched by Aura keep running; the upgrade does not recursively terminate their process trees.

## Validation and limitations

- A local Windows GUI build succeeded. Reading the compiled executable's Windows version resource confirmed that both `FileDescription` and `ProductName` are exactly `Aura`.
- `cargo check --workspace` and the local GUI unit tests passed (32 passed, 4 ignored). The local workspace test run stopped at the French Locale acceptance case: its target observed `en-US` instead of `fr-FR` while this Codex session was already running under Aura's US Profile. This repeats the injected-session limitation recorded for v0.3.3; it is not a clean-host workspace test result.
- Publication requires successful workspace build and test CI on the exact tagged main-branch commit. The release workflow builds the Windows installer and adds its size and SHA-256 below.
- An actual installed-app upgrade and the resulting Task Manager interface have not been manually verified for this release. The resource check verifies the compiled executable; an already-running older installation retains its previous metadata until upgraded and reopened.

This release changes executable naming metadata. It does not change Profile or Runtime behavior.
