# Aura v0.3.5

This patch release fixes memory growth while Aura is hidden in the notification area and makes its tray icon easier to see.

## Changes

- Aura now reuses one image handle for the navigation logo. Previously, every 200 ms tray poll rebuilt the interface with a new image ID. Iced decoded each ID into a separate image-cache entry during layout; while the window was hidden, rendering did not run the usual cache cleanup. Leaving Aura in the tray for hours could therefore accumulate hundreds of megabytes of memory. Reusing the handle keeps those layouts on one cached image.
- The tray icon now uses the same transparent-padding normalization as application-list icons. Its original artwork occupied about 66% of the image canvas, so Windows also scaled down the surrounding empty space. The normalized artwork occupies about 90% of a centered transparent canvas, preserving its aspect ratio and partially transparent edges.
- Regression tests cover reuse of the navigation image ID and the actual bundled tray image's visible size, transparency, and Windows icon construction.

## Upgrade behavior

Open Settings, check for updates, then download and install the update. You can also download `aura-setup.exe` from this release and run it directly. Finish the installation wizard and reopen Aura to use the fixed GUI and tray icon. An older Aura process continues to use its existing image cache until it exits; reopening its window can clear accumulated cache entries temporarily, but updating and reopening Aura is required for the permanent fix.

The installer retains the existing installation directory and local configuration. Applications already launched through Aura keep running; upgrading does not recursively terminate their process trees. Profile and Runtime virtualization behavior is unchanged by these GUI fixes.

## Validation and limitations

- A running v0.3.3 installation reproduced the reported memory growth. Restoring its hidden window reduced the same process's working set from about 970 MiB to 71 MiB and private committed memory from about 1,942 MiB to 302 MiB. These are different memory metrics; the committed-memory value is not all resident physical memory.
- An isolated Windows harness exercised Aura's real view and layout in a hidden window with accelerated tray-poll messages. Between updates 500 and 3,000, the old implementation added 41.39 MiB of private committed memory and failed the growth check. The fixed implementation changed by approximately -0.04 MiB and passed. This verifies the specific image-cache accumulation path, not an hours-long soak or a guarantee about every workload's baseline memory.
- A native Windows notification-area comparison used the production tray constructor alongside the original icon. In the captured 16-pixel icon slot, the visible blue artwork grew from approximately 10 x 10 pixels to 13 x 14 pixels. This is source-build tray evidence, separate from an installed-app upgrade.
- Local GUI unit tests passed: 34 passed, 4 ignored. The GUI build, workspace check, and Git diff checks passed. The local workspace test run stopped at the French Locale acceptance case: its target observed `en-US` instead of `fr-FR` while this Codex session was already running under Aura's US Profile. This repeats the injected-session limitation recorded for earlier releases; it is not a clean-host workspace test result. Clean-host workspace CI on the exact release commit remains the publication gate.
- Publication builds the installer through `scripts/build-installer.ps1`, including the Rust workspace and both x64/x86 Runtime DLLs. The release workflow appends the installer size and SHA-256 below.
- An actual installed v0.3.5 upgrade and an hours-long post-upgrade memory observation have not been manually verified.
