# Aura v0.3.8

Aura now manages reusable environment configurations directly, with clearer application launch controls, Profile identity views, and strict Profile DNS routing. This release also fixes input text escaping its fields and installation blocked by a running Supervisor.

## Changes

- Application selection and launch actions live on the Applications page. Environment configurations manage region, locale, language, timezone, DNS, environment variables, and optional identity values; each new instance receives an immutable snapshot.
- Applications use compact selectable rows, with launch, alternate configuration, host launch, and instance actions in the detail panel. Application and configuration panes resize independently during the session. Forms and DNS menus share the dark styling; longer capability explanations are available through tooltips.
- Optional supported Win32 identity views cover computer name, user name, adapter MAC, and MachineGuid registry reads. MAC and GUID generation modifies only the draft configuration, without changing host identity.
- Arbitrary DNS QTYPEs route through configured UDP, TCP, DoT, and DoH transports. Strict virtual-view DNS returns failure when configured upstreams fail, preventing host-resolver fallback in supported API paths.
- Repeated full-QTYPE queries share a bounded process-local wire-response cache, including DoH service-name bootstrap answers. The new cache ages returned TTLs, expires within the shortest response TTL, separates upstream/TLS policies and query options, and merges simultaneous misses. Explicit cache-bypass and wire-only queries still access their configured upstream. SVCB/HTTPS flat records remain available on older Windows DNS decoders.
- Localhost resolution remains native while Profile DNS is enabled. This fixes Antigravity language-server startup failing with exit code 2 when Windows internally uses a private DNS request version. Public DNS requests continue through Profile routing and validation.
- DoH connection IPs can be left empty. Runtime bootstraps the service hostname through a directly connectable upstream from the same Profile, preserving URL/TLS identity and the original deadline/cancellation. It does not add a default resolver or use host DNS. Without an available bootstrap source, configuration can be saved but resolution fails.
- Saving also validates and includes the DNS upstream being entered, without requiring Add first. Invalid entries show a nearby error; saved editor state is normalized to avoid duplicate upstreams.
- CPU text rendering respects local clipping, keeping GUIDs and URLs within their fields and preserving subsequent dropdown labels/checkmarks and text alignment.
- Supervisor management/recovery retain authoritative snapshot identity and instance ownership across mixed architectures, late replies, generation changes, and uncertain stop results.
- Installer/uninstaller stop only Aura management processes from the chosen installation directory, including Supervisor, preserve launched applications, and check locked payloads before replacement. The finish page launches Aura through the ordinary Explorer desktop session.
- Rust 1.99.0 is pinned for development and Windows CI. The installer packages the GUI, CLI, Broker, Supervisor, probes/helper, and both Runtime architectures.

## Validation and limitations

- Publication requires successful Windows CI for the exact release commit, including workspace build/tests and the separate CPU-renderer regression suite.
- Dual-architecture DoH routing contracts and eight actual injected cases cover controlled UDP/TCP bootstrap followed by public DoH, plus explicit no-source failure. This establishes covered API behavior, not a global network-capture guarantee.
- Cache and route contracts run for x64 and x86 in CI. Controlled routing verifies one transport call for 100 repeated A/HTTPS/SVCB queries and for eight simultaneous cold queries, plus cancellation/deadline while waiting. Injected API acceptance also counts real fixture UDP packets across A/W/UTF8/Ex/async queries and explicit bypass. These checks do not establish public DNS latency or a full application workload improvement.
- This optimization removes repeated work through response reuse. Cold DoH/DoT exchanges still establish connections; persistent connection pooling and trust-snapshot reuse are not part of this change. The existing address-only resolver cache retains its separate policy.
- Antigravity 2.19.1 language-server startup was reproduced as exit 2 with the existing Profile, then verified with the matched 0.3.8 CLI/Runtime: localhost HTTP/HTTPS listeners, successful initialization, and 30 seconds alive. Audit records preserve remote Profile DoH routing. Full IDE login/function testing remains separate.
- Desktop fixtures verified 1400/1100-pixel application layouts, narrow editor clipping, and pending-DoH save/reopen without duplication. Installer helper fixtures cover directory ownership, locks, and ordinary desktop launch. Elevated in-place upgrades across Windows installations and physical-monitor soak testing remain separately unverified.
- Aura provides process-scoped environment information while applications use host files, GPU, networking, and user permissions. It is not a security sandbox. App-owned DNS protocols and unsupported browser renderer/API paths may bypass these views; webpage/account language can differ from browser UI language.
- IPv6 connection discovery/transport and CPU/GPU/disk identity remain deferred. Driver/service prototypes are not a qualified kernel container; Container/Strong enforcement remains unavailable.

## Upgrade

Run aura-setup.exe or use the updater, then reopen Aura. Existing application and environment configuration data is retained. Existing instances retain their snapshots; edits apply to new runs.
