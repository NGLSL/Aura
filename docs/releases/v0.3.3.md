# Aura v0.3.3

This patch release adds update checks and installation to Settings, alongside direct links to the official release page and repository. It also adopts the Apache License 2.0 and adds a LINUX DO community acknowledgement to the English README.

## Changes

- Settings now starts with an **About Aura and updates** card showing the current version, **Check for updates**, **Open release page**, and **Visit repository**. The application interface remains in Chinese.
- Update checks query the latest stable GitHub release only when requested. If a newer version has a verifiable official installer, the action becomes **Download and install**; incomplete release assets direct users to the release page instead.
- Downloads require both `aura-setup.exe` and `aura-setup.exe.sha256`. Aura verifies asset sizes, both GitHub API SHA-256 digests, and the installer hash recorded in the checksum file. It verifies the installer again immediately before launching it and removes partial files after failures.
- Checks, downloads, hashing, and installer startup run in background workers. Duplicate update actions are disabled while work is in progress. Unsaved application or Profile edits prevent installation.
- The installer opens through the native Windows elevation prompt. Aura exits only after startup succeeds; cancellation or failure keeps Aura open and allows retrying. A cached installer that fails verification is discarded so the next attempt downloads it again; cancelling elevation retains a valid installer for retrying. The downloaded installer remains available while NSIS starts, avoiding premature deletion of its source file.
- The README is entirely in English and includes the update workflow and a [LINUX DO](https://linux.do/) community acknowledgement.
- Aura / EnvBox is now licensed under Apache-2.0. Installers include `LICENSE` and the Microsoft Detours third-party notice; Detours retains its MIT license.

## Upgrade behavior

Download `aura-setup.exe` from this release and run it to upgrade. Earlier Aura versions do not include the new in-app update action. Finish the installation wizard, then reopen Aura; subsequent releases can be checked from Settings.

The installer keeps the existing installation directory and local configuration. Applications already launched by Aura keep running: their Runtime DLLs are staged outside the installation directory, and the upgrade does not recursively terminate their process trees. Existing instances retain the immutable Profile and Runtime they received at launch; launch a new instance to use a newer Runtime. The installer does not automatically relaunch Aura with elevated privileges.

## Validation and limitations

- GUI unit tests passed: 32 passed, 4 ignored, including recovery after a cached installer fails verification and retention after installer startup is cancelled. An explicitly invoked live smoke test checked GitHub and downloaded and verified the official v0.3.2 installer without running it.
- An isolated GUI build displayed the new Settings card and successfully checked the live latest release. Simulated available, missing-installer, failure, and busy states were also checked. These are source-build UI results, separate from installed-app validation.
- The complete Windows packaging command builds the Rust workspace, x64/x86 Runtime DLLs, and NSIS installer. The release workflow requires successful CI on the exact tagged commit and adds the installer size and SHA-256 below.
- A local full-workspace test run from an Aura-injected Codex session failed the French Locale acceptance case: the target received the outer session's US Profile. It also failed when explicitly selecting the current release Runtime. This local run is not a clean-host test result; the unvirtualized GitHub Windows runner supplies the release CI gate.
- Interactive UAC cancellation, an actual installed-app upgrade, and post-upgrade launch have not been manually verified for this release. No additional local GUI or installer interactions were performed for publication.

Update checks and downloads require access to GitHub and the Windows system `curl.exe`. There is no startup update polling or silent installation. Aura does not change global Windows Locale, Region, or Timezone and does not provide a security sandbox.
