# 2026-10-25 性能优化对照

本轮完成 GUI 后台任务、分栏保存合并、托盘事件推送、Runtime 热路径、启动校验和 Supervisor 等待方式的优化。所有测量在同一台 Windows x64 机器上进行，未覆盖或重启已安装的 Aura，也未新增测试用例。

## 对照版本与方法

- 基线：`deafc5fdd46f64c95624f5b1c41765dc536c469e`，v0.3.16。测量时使用保持干净的独立 detached worktree；发布整理时移除该临时检出，基线提交仍可重新检出。
- 优化版：该提交之上的本地工作区修改，测量构建版本号为 v0.3.16；性能改动随后随 v0.3.17 发布。
- 本报告的数据对应字体和分栏布局整理前的性能归档构建；准确改动保存在 `target/performance-20261025/source-changes.patch`（SHA-256：`661BDAE97C650863159F66B0D5CA66A308703DBF4981705FB79D7F6545C6D7AE`）。后续 13 号字、固定编辑操作栏及动态最小栏宽的 UI 改动未计入本报告数据。
- GUI 状态、启动链和 native API 对照使用 Release 构建；两套 Runtime 均使用 CMake/MSVC Release，包含实际 x64/x86 DLL 和 Detours。
- 当前开发终端本身由已安装 Aura 启动，继承了旧 Runtime。实际测量与既有检查均由 Explorer Desktop COM 对象启动隐藏控制进程；控制器先记录模块和环境，确认没有 Runtime、没有继承 `ENVBOX_*`，随后再设置隔离测量配置。
- Profile 目标实际读取自己的模块路径，再独立计算已加载文件的 SHA-256，与相应 before/after DLL 比较。Host 对照实际没有 Runtime。两组不共享用户配置或浏览器数据。
- 编译、功能检查、GUI 性能、native 性能及 Supervisor 空闲测量按时间窗口顺序执行，避免它们彼此争用 CPU。
- GUI 每条件预热后取 8 个样本；p95 使用 nearest-rank，n=8 时即最大值。小样本分位数仅描述本轮分布，不作为全机器保证。

原始文件保存在仓库忽略的 `target/performance-20261025/`。`before/`、`after/` 分别保存相干的可执行文件与两架构 DLL，附有 SHA-256 清单。该目录也保留临时 benchmark 源码、控制器、完整日志和原始样本。发布整理仅移除可重建的 Cargo/CMake 构建目录与临时基线检出；含真实审计快照的原始数据仅在本机保留，不加入提交或公开安装包。

### 分栏保存

同一脚本产生 200 个不同的 resize 事件。请求间隔 2 ms，Windows 实际调度间隔约 15 ms；两版本使用相同节奏，并等到尾沿比例保存完成。

| 指标，中位数 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 所有 update 的累计处理时间 | 251.01 ms | 28.47 ms |
| 可观察的 `ui.toml` 内容更新次数 | 200 | 13 |
| 包含尾沿等待的整个输入序列时间 | 3104.74 ms | 3346.68 ms |
| 每轮最大单次 update | 3.88 ms | 4.80 ms |
| 最终持久化比例 | 0.7000000476837158 | 0.7000000476837158 |

累计 UI 处理时间减少约 88.66%，文件内容更新次数减少 93.5%。计数来自每个消息之后对配置文件内容的观察，不是 SSD 物理写入次数。尾沿保存要等待约 250 ms，整个序列因此更长；单次最慢 update 也没有改善证据。每个分栏的首次变化仍立即保存，连续变化合并，退出前刷新最终值。

## 启动链、Runtime 与后台监控

启动校验保留源文件、缓存文件与已加载 Runtime 身份检查。逐字节 FNV 内容指纹换为已有 `sha2` 的 SHA-256；目录键保持原来长度，文件内容仍使用完整 SHA-256 比较。缓存命中时，辅助 EXE 改用分块比较，避免同时保留两份完整 EXE。DNS 与 identity 能力预检共用同一份有界 PE 字节。

### 实际启动与 Job 查询

小型 native 目标只采集必要身份后退出，同批交替运行 before/after；下表启动条件各有 20 个有效样本。缓存准备同样为 20 轮热命中。Job 条件各运行 7 轮，每轮查询 10,000 次，子进程由临时 benchmark 自己创建并结束。

| 场景 | 优化前中位数 / p95 | 优化后中位数 / p95 | 中位数减少 |
| --- | ---: | ---: | ---: |
| 两架构 Runtime bundle 热命中准备 | 13.011 / 13.217 ms | 7.569 / 8.636 ms | 41.8% |
| Profile → native 目标完成，审计关闭 | 144.262 / 155.984 ms | 136.012 / 138.651 ms | 5.7% |
| Profile → native 目标完成，审计开启 | 151.579 / 159.164 ms | 139.359 / 150.109 ms | 8.1% |
| Job 存活查询，0 个子进程，10,000 次 | 8.195 / 8.486 ms | 3.933 / 4.181 ms | 52.0% |
| Job 存活查询，32 个子进程，10,000 次 | 145.951 / 151.403 ms | 127.916 / 137.335 ms | 12.4% |

另有完整 `envbox-probe` 的前后 15 轮采样：Host 中位数 403.876 → 348.372 ms，Profile 693.522 → 590.086 ms，Audit 685.186 → 593.442 ms。Host 自身也快约 13.7%，说明两批存在系统或快照采集波动。不能把完整 Probe 的约 14.9% Profile 变化全部归因于本次优化，实际启动收益以同批交替的小型目标为主。

### Runtime 热路径

每个线程调用 100,000 次，每条件 5 轮。时间采用最慢线程的 QPC API 循环区间，排除线程创建、join 和预开句柄准备；4 线程条件合计执行 400,000 次。原始数据同时保留包含这些准备工作的 wall time。

| 条件 | 优化前中位数 | 优化后中位数 | 变化 |
| --- | ---: | ---: | ---: |
| 审计关闭，LCID，单线程 | 4.8105 ms | 0.5226 ms | -89.1% |
| 审计关闭，UI LANGID，单线程 | 6.3076 ms | 0.7464 ms | -88.2% |
| 审计关闭，GetLocalTime，4 线程 | 69.7377 ms | 52.3996 ms | -24.9% |
| 审计关闭，400 个预开注册表句柄，4 线程查询 | 92.5529 ms | 56.8033 ms | -38.6% |
| 审计开启，LCID，单线程 | 5.9796 ms | 6.7422 ms | +12.8% |
| 审计开启，LCID，4 线程 | 30.5229 ms | 32.5800 ms | +6.7% |

开启审计的 LCID 小循环存在回退，单线程绝对增加约 0.763 ms/100,000 次。保留这一结果，不宣称所有 API、所有审计状态都更快。此负载连续调用同一种 API，会触发重复事件折叠，不能用它推断混合 API 持续刷盘的卡顿已解决。

540 条计时样本完成，注册表调用失败计数为 0，54 组前后 checksum 一致。失败计数只针对注册表 API；时间和语言 API 的结果由 checksum 及完整 Probe 静态字段共同核对。

### Supervisor 空闲等待

这项使用 Debug 构建、真实 `serve`、独立空配置进程，仅修改端点 namespace。每版 3 轮，每轮 10 秒，按 AB / BA / AB 顺序运行。它衡量服务线程，不等于安装版整个应用或整机耗电。

| 指标，中位数 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 服务线程 CPU cycles / 10 秒 | 116,107,179 | 2,731,623 |
| 服务线程 CPU 时间 / 10 秒 | 15.625 ms | 0 ms，低于本轮计数粒度 |
| 独立进程私有内存 | 1,482,752 B | 1,474,560 B |
| 每轮 10 秒私有内存增量 | 均为 0 B | 均为 0 B |
| 设置 stop 标志到线程退出 | 9.396 ms | 93.653 ms |
| 最大 stop 延迟样本 | 10.750 ms | 107.090 ms |

服务线程 CPU cycles 中位数减少 97.65%。Windows CPU 时间样本以 15.625 ms 粒度出现，优化后的 0 ms 表示低于计数粒度，不能称为零开销。停止标志最多每 250 ms 检查一次，实测停止响应相应延后；这一取舍不隐藏在 CPU 收益中。

## 内存

小型 native Profile 目标的私有内存中位数，在 GUI 启动对照中前后均为 **3,334,144 bytes，约 3.18 MiB**；工作集约为 10.19 → 9.96 MiB。这是特定目标和采样时点，不能外推到浏览器或完整进程树，也不能据此承诺常驻内存减少。

其他实际采样结果如下；长循环为结束时单次进程端点，缺少完整稳定性曲线：

| 采样对象 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 长 hot-loop，Profile 私有内存 | 2.70 MiB | 3.21 MiB |
| 长 hot-loop，Audit 私有内存 | 3.11 MiB | 3.20 MiB |
| 长 hot-loop，Profile 峰值工作集 | 10.64 MiB | 10.52 MiB |
| 长 hot-loop，Audit 峰值工作集 | 10.82 MiB | 10.79 MiB |
| 临时 launcher 完成 bundle 准备后私有内存 | 约 0.98 MiB | 约 0.98 MiB |
| 临时 launcher 峰值工作集 | 约 5.61 MiB | 约 5.61 MiB |

内存结果没有统一下降，个别端点增加。端点分配器波动无法证明长期常驻上限，既不将工作集小幅下降解释为普遍节省，也不把静态索引空间当成整个进程内存变化的唯一原因。

注册表句柄索引增加两个固定 `int[512]` 数组，静态空间约 **4 KiB/注入进程**。Runtime 没有新增后台写入线程。GUI 审计和启动线程仅承担本次工作；状态 benchmark 没有窗口或渲染器，其内存记录不作为完整 GUI 内存结果。

辅助 EXE 分块比对减少双份完整内容的同时存活，这一点由实现确认。本轮没有采集启动父进程对应的完整峰值曲线，因此不将它量化为已实测的常驻节省。

## 实现范围与正确性

- 审计后台加载：并发刷新合并，旧结果不覆盖新一轮状态；完整有效记录总数、全局最新 500 条及相同时间戳顺序保持一致。
- GUI 后台启动：冻结启动时的 Application/Profile/Detect 参数，只交接新实例所有权；已有实例复用保持成功语义，Windows Terminal 在后台完成 handoff 后再返回。启动尚未完成时暂缓退出，托盘退出被拦截时恢复窗口显示原因。
- 分栏保存：首次立即保存、连续变化合并、尾沿保存、正常退出及启动安装器前刷新。
- 托盘：利用现有回调推送事件，删除 200 ms 空轮询；不新增监听线程。
- Runtime：保持 512 个注册表路径槽及满容量淘汰规则，增加有界句柄索引；相对路径、句柄关闭/复用保留。缓存不可变 UI LANGID；审计关闭时跳过日志专用格式化；时区命中采用共享读锁，保留瞬时错误重试及实时 DST 判断。
- 会话存活：只读取 Job 进程数量，不额外枚举完整 PID 列表；查询失败仍保留会话。
- Supervisor：连接、读取和写入统一使用有效 OVERLAPPED，超时或取消后先取消并等待 I/O 结束，再释放缓冲和事件；保留认证、请求时限和 250 ms 状态刷新。

本轮保留 DNS 长连接和同步审计 sink。DoH 验证器、取消回调及所有内部任务目前按单次查询清理；连接跨查询存活需要重新定义其生命周期。审计缓冲和退出刷新也有现有契约，本轮先减少关闭审计时的热路径成本，没有改变刷盘线程、刷新阈值或崩溃丢失窗口。
