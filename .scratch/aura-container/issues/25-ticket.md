# 25: 网络创建窗口、组件故障及服务代执行门禁

Stage: P4
Status: ready-for-agent
Parent: [总规格](../spec.md) · [完整实施规划](../implementation-plan.md)

**What to build:** 证明严格网络策略在创建及故障窗口持续有效，并明确不能归属的服务代执行应用边界。

Blocked by: [24](./24-ticket.md)、[12](./12-ticket.md)

## 负责模块与契约

网络原型资格测试、启动事务对接、代执行支持报告。

保持总规格的稳定Container/Instance身份、不可变Run快照和host/A/B独立对照。修改限定于本票职责；保留其他Agent改动。关键契约变化或未证明机制需报告证据，由主Agent决定，不静默降级。

## 不包括

不把服务PID认领给单一Container，不关闭sandbox，不全局修改共享服务。

## 验收标准

- [ ] 在目标第一条应用连接前策略已绑定；创建/Resume竞争压力测试无未授权数据包，记录时序与负向证据。
- [ ] Supervisor、DNS组件、可信通道及驱动的故障分别验证既有保护不退回Host；不可维持则按已证明策略拒绝或停止目标。
- [ ] WMI/COM/Shell/共享服务代执行分别列真实归属结果，无法可靠归属的严格目标拒绝或不进入支持矩阵。
- [ ] host/A/B同exe并行测试与PID复用不发生跨环境放行、封禁或误杀。
- [ ] 输出P4门禁结论、缺口和允许的正式集成能力；任一声明内缺口阻塞36而非记Partial通过。

## 验证证据

门禁：失败报告是必要交付，但不解除36的行为依赖。声明内缺口未解决时本票保持未完成/阻塞，后续不得以“调研已完成”开展正式集成。

经公共CLI、真实注入/内核Probe或本票指定的资格入口验证可观察行为，保存配置快照、系统/组件版本、模块路径与hash、host/A/B原始结果和失败原因。需要驱动、故障或危险系统配置的验证只在明确隔离测试环境执行；本票不授权宿主安装、外部申请或发布。静态检查、fixture、隔离环境、实际安装与真实应用证据分别列出；未执行、缺材料、权限不足及skip不得算通过。文档预检票保存可复现检查与来源，不伪造运行证据。
