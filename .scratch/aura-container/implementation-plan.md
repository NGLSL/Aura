# 环境信息容器实施规划

Status: ready-for-agent
Date: 2026-10-06
Parent: [当前总规格](spec.md)

## 当前目标

以持久环境容器管理 Profile 和进程树，提供经过验证的环境信息视图。用户本次澄清取代旧 P0–P8 存储/权限隔离路线；不再以驱动、文件 COW、Registry 写隔离或完整网络出口限制作为完成条件。

已有用户态基础、DNS 和恢复成果先核对后复用，不重新实现。旧源码、快照格式与用户配置保留；本规划不启用 Container/Strong 枚举、不安装服务/驱动，也不引入 Sandboxie/AppContainer 作为本目标的新依赖。

## 顺序与验收

| 工作包 | 实施内容 | 产物及门槛 |
| --- | --- | --- |
| R1 信息读取盘点 | 按已有 Profile 字段、实际 Hook、Probe 和目标程序建立矩阵；单列 hostname/user/MAC/硬件等候选 | 每入口记录 Profile 来源、实际是否覆盖、宿主对照、限制和待验证项；候选不能自动扩范围 |
| R2 已有字段的一致性 | 优先修现有 Locale/Language/Region/Timezone/Env/白名单读视图的具体差异 | 按真实读取入口修改必要代码，Hook 同步 Probe；E01–E03/E08；无差异不增加 Hook |
| R3 DNS 与浏览器路径 | 保留四传输、任意 QTYPE、strict；分开验证 Windows resolver、应用 resolver、renderer 和 WebRTC | E04；既有失败/未验证项保留，实际浏览器覆盖记录准确；IPv6 后置 |
| R4 产品用语与保证 | 核对 GUI/CLI 的容器、Profile、字段和 Coverage 用语；保留原配置兼容性 | E07；信息视图不显示文件写保护/完整匿名，失败行为按当前声明能力判断 |
| R5 最终矩阵 | 汇总不可变快照、子进程、恢复、Host/A/B、真实应用与资源检查 | E01–E08逐项验收；缺项不自动标完成，虚拟机/驱动资格不作为新门槛 |

R1先于新增信息能力或扩大应用保证。R2与R3有独立模块和稳定契约时可并行；R4使用已核对的事实，R5在修复冻结后执行。新增 hostname/MAC 等字段需先确定目标读取链路、字段语义与多入口一致性，再生成独立票，不能把“所有可能泄漏信息”视为无限开发范围。

## 现有票与代码的处理

- 旧01–13中的启动、身份、快照、工作区、Supervisor与恢复工作可复用。按当前E01/E03/E05/E08核对，已有证据不重标为待实现，旧安全边界要求不继承。
- 旧14–20 DNS独立能力继续适用，范围以当前DNS规格为准，不受旧P4–P8资格阻塞。
- 旧21–49整体隔离后端路线退出当前执行frontier。内核、COW、独立hive、驱动交付与旧F01–F10不是本项目本次目标的必需项；对象/浏览器读取覆盖中仍有价值的部分重新按R1评估，不整票搬入。
- `drivers/envbox-policy`和`envbox-policy-service`保留为未部署实验成果；不继续沿旧依赖链实施，不把保留代码当作当前容器必须依赖。
- 历史状态、失败日志、commit与证据保持原样；新范围不将旧P0–P8宣称完成，也不要求为了新目标清除它们。

## 验证纪律

Profile一致性以实际未注入Host和已注入A/B读取作对照。API支持与应用支持分开；父进程结果不能代替子进程/renderer结果。使用固定模块hash、配置快照、实际身份、原始Probe输出和可定位错误。

现有strict DNS失败不得回退宿主。其他信息Hook先定义具体失败语义，不粗暴全局改Fail Open；未覆盖入口通过Coverage如实报告。是否“减少信息泄漏”必须关联能力与入口，不提供任意恶意程序无法读取宿主的安全承诺。

只对实际变更运行必要检查；纯文档改范围验证链接、旧路线路由和内容一致性，不重跑Rust/Runtime全量测试。代码实施按每票风险验证，完成后统一review。安装、发布和删除用户数据需相应授权。
